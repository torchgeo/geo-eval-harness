# Compute measurements, 12 November 2026

The sweep adds 2,708 validated measurements (1,860 segmentation) to `compute_cost.csv`, preserving all 508 historical rows. Those rows retain their original field values and are labeled `measurement_variant=legacy_unverified`; validation in this report applies to the new identified measurements. It covers all 143 model names with checked-in benchmark results, including all 83 segmentation model names. `compute_cost_coverage.csv` lists every requested model, band selection, image size, and head, including unsupported combinations. `compute_cost_provenance.json` records checksums, hardware, backend versions, source archives, and the measurement window.

## Protocol

Each GPU runs one model at a time on an NVIDIA RTX PRO 6000 Blackwell Server Edition with 96 GB of memory (`g7e.12xlarge`, two GPUs). Measurements use synthetic float32 inputs, batch size 1, five warmup passes, and twenty synchronized timed passes. Throughput excludes dataset reads and host-to-device transfers. The segmentation output has four classes. Classification rows include a ten-class linear probe in FLOPs; their throughput measures the backbone embedding forward. Segmentation rows count and time the complete backbone, neck, and decoder forward at the same resolution. `gflops_head` includes the neck. Parameters describe the architecture; decoder weights are initialized for profiling rather than trained.

The default image sizes are 224, 256, and 512 pixels per side. Panopticon uses patch-aligned sizes 224, 252, and 518. EarthLoc is measured once at its native 320-pixel grid because its learned spatial aggregation fixes the token count. TerraFM retains its learned position tensor and interpolates positions during the forward pass, with wrapper resizing disabled. AnySat and UniverSat use native sensor GSD, so larger images cover more ground; their physical patch sizes are not pixel token counts. Their derived `n_tokens` fields are omitted without changing measured metrics.

The heads are linear, UPerNet, and UNet. Equal-resolution transformer maps receive the ViT pyramid neck, including neck + linear; native feature pyramids retain their spatial scales. Rows record the actual neck, taps, and feature shapes. Only models declaring spatial taps receive segmentation profiles. RGB and all CloudSen12 Sentinel-2 bands are attempted where supported; SAR presets use Kuro Siwo metadata. Unsupported band or tokenizer combinations are recorded explicitly in the coverage file (15 presets have at least one unsupported choice).

AnySat classification additionally has a separately labeled `measurement_variant=s2_patch80_reference` at the authors' 80 m Sentinel-2 physical patch setting (8 pixels at native 10 m GSD). The catalog default is 10 m (1 pixel); its six RGB/all classification attempts OOM, including an individual 3 TiB attention allocation at 512. Those OOMs remain in coverage with the default configuration hashes. The reference is a different patch configuration, not a recovered measurement of the default. The AnySat segmentation preset already uses the 80 m recipe.

## Interpreting the numbers

One multiply-add counts as two FLOPs. PyTorch's counter covers registered operators; unregistered operations can make totals lower bounds. The zero registered backbone counts for the handcrafted/statistics controls do not mean those controls perform no computation; their measured throughput remains meaningful. These are inference measurements, not training cost estimates or saturated batch-throughput measurements. These are controlled reference inputs rather than separate measurements of every model/dataset configuration. Dataset-specific channel selections, temporal lengths, output classes, and adaptation settings can change compute cost. Do not mix the historical GPU measurements with this GPU cohort when comparing throughput. The leaderboard's compute reference selects the latest common hardware cohort at 224 pixels for classification; the explorer retains all measured sizes and heads.

The validation checks finite FLOPs and timing metrics, unique measurement identities, actual feature geometry, unchanged decoder parameter counts across image sizes, `total = backbone + neck/head`, matching backbone FLOPs across classification and segmentation heads, and nondecreasing FLOPs as image dimensions grow within each model/band/head configuration. Every measured coverage cell has a corresponding validated CSV row. The final local Python suite passed 3,013 tests (69 skipped and 211 deselected), including the native-grid and checkpoint regressions. Pre-commit and Sphinx checks passed. These checks support reproducibility; they do not certify complete operator coverage or guarantee benchmark accuracy.

## Reproduction

Baseline `f67a8916ebd7b9e7b1669eacb10c5c75eed70200` plus the profiling changes in this checkout. Run `python experiments/run_compute_cost_sweep.py --image-sizes 224 256 512 --heads linear upernet unet --device cuda:0 --output results/compute_sweep`. Local checkpoints can be supplied with `--model-kwargs-file`. Immutable source archives, exact per-cell YAML, logs, coverage reports, and environment package lists are retained in the private S3 artifact location in the provenance JSON. TerraMind RGB row names are aligned to their declared RGB preset names so they join the benchmark results; the archived profiler emitted the S2 aliases. Only this identifier metadata is corrected, as recorded in the provenance JSON. Main and repair phases use separate recorded source fingerprints; repaired configurations replace failed or superseded attempts in this table.

OlmoEarth v1.3 profiles use the runtime-only implementation from PR #566 at `b2b7989e362841164c74005dd21ffa46df0c39f4`, with `olmoearth-pretrain-minimal==0.1.5` in a separate interpreter sharing the same PyTorch stack. That implementation is included in the archived runtime source, but is not merged into this checkout. SAM 3 uses the authorized local Hugging Face snapshot recorded in the provenance file; no Hugging Face token was copied to the instance. TerraFM uses the official checkpoint with its recorded revision and SHA-256. Other wrappers use their pinned checkpoint definitions and archived backend versions.
