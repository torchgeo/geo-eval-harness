Geo Eval Harness Geospatial Foundation Model Ranking

Geospatial foundation models are pretrained backbones, with the promise of being easily adaptable to various earth observation downstream tasks. Geo Eval Harness is a collective effort to provide transparent and fair evaluations of these models on established protocols such that the community can gain a better understanding of model performance across tasks.

The table summarizes per-dataset scores, and four settings provide different views of the results:

  • Aggregation sets how the per-dataset scores are combined into a single number.
  • Task switches between classification (per-image label) and segmentation (per-pixel mIoU) benchmarks.
  • Probe sets how frozen embeddings become predictions: a fitted linear classifier or KNN-5 for classification, or a linear/DPT/FPN/conv-block decoder head for segmentation.
  • Bands sets the input modality for the backbone that configures the required bands and order, either RGB or the available multispectral channels.

Each setting is a separate experiment rather than a filter applied to one result, so the table can reorder when you change one of them. A model is ranked only when it has a result on every eligible dataset in the selected view, and the models that fall short are named below the table. The evaluation setup documents the protocol, the coverage rules, and how each aggregation is computed.

If a result looks wrong, is missing, or seems implausible, please open an issue with the model, the view you were looking at, and any supporting evidence. General feedback is of course welcome too.

Ranking sensitivity across views

Pick which experiments to compare, using average rank. Each cell asks whether the same models land in the same order in two views: it keeps only models available in both, re-ranks them using every dataset available in each, and then calculates tie-aware Kendall τ-b. +1 means the same order, 0 little agreement, and −1 a reversal.

Each cell reports τ-b, shared models (n), and datasets in its row and column views (d). A dagger marks a small shared roster — read those cells with caution, especially across tasks where few models overlap.
