# Classification refresh

The evaluation source is `4c8693320629fec9df030bbb04062ebdde6a6f3c`, which adds finite-score validation to main commit `0d77903451d717b220d10791d3e532b84b6acd78`. Linear probing rejects non-finite validation probabilities for both label types and non-finite test probabilities after refitting. Results generated before these checks were deployed are rerun. The sweep discovers image models from the current preset catalog and classification datasets from the dataset registry. Infra-Bench CLS, EoS-FM, and Tessera are excluded. Coordinate encoders, segmentation presets, alternate pooling presets, and duplicate aliases are excluded. Model-declared dataset restrictions remain enforced.

Classification uses KNN-5 and linear probing with seed 0, 200 bootstrap samples, the default 40-point regularization search from 10^-6 to 10^4, and train/validation refitting. Preset-specific linear search overrides are retained, including TerraMind’s 60-point search through 10^5. Image size, interpolation, temporal inputs, sensor mapping, and model-specific preprocessing come from the presets. RGB and all-band inputs are evaluated with dataset and model normalization where supported. OlmoEarth uses its internal normalization; AnySat and UniverSat use dataset normalization. Handcrafted features use their preset inputs. ImageStats requests the default dataset normalization and returns raw inputs.

Models with an existing pooling option use mean patch pooling. OlmoEarth uses `patch_tokens`; Panopticon retains its existing CLS descriptor. Models without a configurable token-pooling interface retain their existing representation. CLS comparisons use a separate [companion protocol and coverage ledger](classification-cls-20261115.md).

`python experiments/plan_classification_refresh.py --output plan.json` writes the complete job configurations and declared exclusions without loading weights or downloading datasets. The plan contains 7,265 active configurations across 141 presets and 15 datasets. Each job requests both evaluation methods. Runtime batch size starts at 64, or 4 for AnySat/UniverSat; an out-of-memory retry reduces batch size and records its resulting configuration hash. GPU devices, dataloader workers, and cache locations may be changed without changing scientific settings.

AWS workers use a private, run-specific output location and never resume from the repository's existing result files. Each retry gets a fresh output file. Completion requires both methods, matching configuration identity, finite metrics, valid confidence intervals, and the expected dataset label and split semantics. If linear probing cannot produce finite probabilities, an independently validated KNN row can be retained with explicit partial coverage and no linear score. Collection replaces stale classification rows after coverage auditing; segmentation rows are preserved. The per-configuration ledger in `results/coverage/classification-refresh-20261114.csv` records 5,608 complete configurations, 22 KNN-only numerical partials (all EfficientNet-B1 with dataset normalization), 1,665 exclusions, and four runtime deferrals, with no pending evaluations. These contribute 11,238 fresh classification rows. Unsupported cases must have explicit exclusion reasons, and failed evaluations cannot retain old scores as substitutes.

The environment uses the repository's lockfile with the `dev` and `olmoearth` extras, plus the documented TerraTorch source revision `89a3ed13d7a6272c009c4c5fbabf62461fcfb16c`. The AWS environment additionally pins `huggingface-hub==1.15.0` and `diffusers==0.35.2` to keep the TerraTorch and Transformers dependencies compatible. The complete installed environment, job configurations, attempt logs, and statuses are retained with the run artifacts.

TerraFM uses `TerraFM-B.pth` from Hugging Face `MBZUAI/TerraFM` at revision `3631173fec2c3a445a71e15985e0f3d5aaf4ecb3`, verified against SHA-256 `8bdb6a4cfd707a09d79f4790119daa9d76bb316b6ea756c6eb305f99d1797a06`. The run configuration supplies its local checkpoint path and MD5 `4f38e4ad30f908c0aa8534d473e99f3f`.

Configurations projected to exceed 20 hours on the selected AWS GPUs are deferred. The initial deferred cases are OlmoEarth nano six-frame on AID and UniverSat on m-brick-kiln, each with RGB and all-band inputs. The manifest and coverage ledger retain these four configurations with explicit deferral reasons.

ImageStats rows record `identity` normalization because the encoder returns raw statistics regardless of the requested normalization. Collection retains the default `dataset` request, whose hashes match current default runs, and excludes the redundant `none` requests. Scores and configuration hashes retain their original values; the coverage ledger records the 30 redundant configurations as excluded.
